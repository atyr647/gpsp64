# Add hot regions discovered via PROFILE_AOT here.  Keep ranges tight

0x08006000  0x08007000        # text engine page (GetStringWidth helpers)

# Added from profiling the animated title screen with native/bench.sh:
#   BENCH_INPUT=none ./native/bench.sh anim
#   tools/suggest_targets.py bench-results/anim.pages
# Only the highest-value Thumb pages are included: the long tail of small
# pages roughly doubles generated code size for ~1% each, which is a poor
# trade for N64 RAM.  Percentages are share of interpreted instructions.
#
# DO NOT add the page containing idle_loop_target_pc (0x080008CE for
# Emerald, i.e. page 0x08000000).  Measured on ares: adding it drops the
# game from 6.9 to 3.3 FPS and zeroes the idle-skip counter, because an
# AOT function whose internal loop covers that PC never returns to the
# interpreter, so the idle-loop fast-path in cpu.cc can never fire.
# cpu.cc now also refuses to AOT that page at runtime as a backstop.
0x08007000  0x08009000        # 13.6% - adjacent to the text engine page
0x082DF000  0x082E1000        # 10.8% - sprite/OAM helpers
# Measured and REJECTED (native/ares_bench.sh): adding the hottest
# remaining call-target pages 0x082E7000 and 0x0800B000 cost 65 KB of
# .text and made things slower -- 12.82 -> 12.50 FPS -- while interpreted
# work barely moved (653K -> 649K insns/window). AOT coverage is not
# monotonically good on N64: past a point the extra code costs more in
# VR4300 I-cache pressure (16 KB) than it saves in interpretation.
